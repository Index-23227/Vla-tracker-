# Galaxea G0.5: One Autoregressive Stream for Robot Reasoning and Action

> **한 줄 요약**: "VLM을 인코더로 강등시키고 별도 flow-matching expert를 붙이는" 현재의 VLA 표준 레시피를 정면으로 거부하고, 단일 Qwen3.5 2B 디코더가 **추론 토큰과 행동 토큰을 하나의 next-token 목적함수**로 생성하도록 만든 autoregressive VLA. 학습형 cross-embodiment ActionCodec(RVQ) + native CoT + 시각 메모리 3종으로 AR의 고질적 토큰 폭증 문제를 제거하고, LIBERO 98.9 / RoboTwin 2.0 93.3 / SimplerEnv-Bridge 87.3 / BEHAVIOR 0.3136 / 실기 76.7%를 달성.

## 1. 배경 및 동기

### VLA 아키텍처의 진자 운동
초기 VLA(RT-2, OpenVLA 등)는 **autoregressive 인터페이스**를 썼다. 연속 행동을 이산화해 언어 vocabulary에 붙이고 VLM이 텍스트와 함께 예측하는 방식이다. 이 구조의 장점은 명확하다 — **VLM 자신이 actor**로 남는다. 문제는 스케일링이었다. 제어 주파수, action horizon, action dimensionality가 커질수록 timestep당 action token 수가 급증해 고주파 제어가 느리고 비싸진다.

이 병목이 필드를 **VLM-as-encoder** 구조로 밀어냈다. 사전학습된 VLM이 hidden state나 KV cache를 공급하고, 별도 파라미터·별도 목적함수를 가진 flow-matching / diffusion expert가 연속 action chunk를 예측한다 (π0, π0.5, GR00T-N1.5 등).

### 저자들이 지적하는 구조적 대가
이 전환은 action 효율은 개선했지만 **VLM의 역할을 바꿔버렸다**. VLM은 더 이상 행동 생성자가 아니라 vision-language 조건 인코더다. 결과적으로 VLM의 핵심 생성 능력 — chain-of-thought 추론, in-context learning, prompt 기반 motion steering — 이 **압축된 conditioning bottleneck을 통과한 뒤에야** 행동에 영향을 줄 수 있다.

### 핵심 질문
- **AR의 원래 비효율(과도한 action tokenization)만 제거하면, VLM을 actor로 되돌려도 foundation-model 스케일에서 작동하는가?**
- **추론과 행동이 같은 stream을 공유하면, VLM의 능력이 실제로 물리적 행동으로 전이되는가?**

> ❓ **예상 질문**: "AR vs FM" 논쟁은 이미 FM 승리로 끝난 것 아닌가?
> **답변**: 저자들의 주장은 FM이 이긴 게 아니라 **AR이 잘못된 tokenizer를 썼기 때문에 진 것**이라는 것이다. 논문은 관련 연구로 VLA-0([18])을 인용하는데, 수정 없는 VLM을 action-as-text로 AR 학습시키면 π0.5-KI를 능가한다는 결과다. G0.5는 여기에 학습형 codec을 더해 스케일 문제를 푼다.

## 2. 방법론 심층 분석

### 2.1 전체 구조

Qwen3.5 2B에서 초기화. 추론 시 입력은 (i) K개 카메라의 multi-view RGB 짧은 시간 윈도우, (ii) embodiment identifier e (예: R1-Pro), (iii) 자연어 지시 ℓ, (iv) proprioceptive state s_t.

전체 시퀀스는 두 구간으로 분할된다:
- **Conditioning segment**: 이미지·embodiment·task·state를 user-side chat token으로 감싸고 `<EOC>`로 종료. **loss 없음**.
- **Generative segment**: CoT trace + action code를 assistant-side chat token으로 감싸고, `<EOV>`가 reasoning↔action 경계를 표시.

학습은 generative segment에만 계산되는 표준 next-token cross-entropy:

```
ℒ(θ) = −Σ_{i∈𝒢} log p_θ(x_i | x_<i)
```

**결정적 지점**: 이 단일 loss가 CoT 생성과 action 생성을 동시에 지도한다. 사전학습에 auxiliary regression objective도, expert distillation도 없다. 디코더 입장에서 CoT와 action은 전부 "그냥 토큰"이다.

비교/선택적 배포용으로 π0.5의 action-expert 구조를 따르는 flow-matching head를 AR trunk의 hidden state에 조건화해 추가로 붙일 수 있다 — 이것이 5.6절의 controlled ablation을 가능하게 한다.

### 2.2 Structured Action Tokenization (핵심 기여 1)

기존 방식의 두 결함을 명시한다:
- **(a) 구조적 분해 부재**: 대부분 전체 action space를 하나의 벡터로 flatten한 뒤 이산화 (FAST 포함). embodiment topology나 실제 제어 DoF를 무시하므로 의미적으로 엉킨 토큰이 나오고, token 수가 전체 제어 가능 DoF에 비례해 증가한다 — 실제로는 매 timestep 소수 관절만 움직이는데도.
- **(b) 토큰 일관성 부족**: 구조적 제약 없이 학습된 이산 action space는 의미적으로 유사한 행동을 Hamming distance가 큰 토큰 시퀀스로 매핑한다. VLM 학습의 supervision 신호로서 상당한 최적화 노이즈가 된다.

**해법**: FASTer의 action grouping 전략 + ActionCodec의 학습 레시피.

1. 로봇을 독립적 **motion part**로 분해 (left control, right control, lower body)
2. 각 part를 공유 최대 차원으로 padding 후 grouped action에 대해 **Residual Vector Quantization (RVQ)** 학습
3. **temporal contrastive objective**를 추가해 시간적으로 인접한 motion 간 토큰 일관성 개선
4. tokenization 시 구조적 special token 주입: R번의 residual round, 각 round는 현재 **활성** DoF-group marker(`<left_control_r>`, `<right_control_r>`, 선택적 `<lower_body_control_r>`) 뒤에 8개 action code

**Active-part tokenization**의 실익: 비활성 part는 padding 없이 stream에서 아예 **제외**된다. 놀고 있는 팔에 토큰을 낭비하지 않는다.

통합 action space는 **27차원**:
```
<left_control>(9) | <left_gripper>(1) | <right_control>(9) | <right_gripper>(1) | <lower_body>(7)
```
해당 embodiment가 구동하지 않는 slot은 merge 시점에 **noop token**으로 채워진다. 따라서 형태가 다른 embodiment들이 **per-robot adapter 없이** 하나의 output head를 공유한다.

> ❓ **예상 질문**: FAST와 무엇이 근본적으로 다른가?
> **답변**: FAST는 고정된 DCT 기반 파이프라인을 **embodiment마다 별도로** 적용한다. G0.5의 codec은 **end-to-end 학습형이며 설계상 cross-embodiment**다. 14개 embodiment가 하나의 이산 인터페이스를 공유한다는 것이 foundation-model 스케일에서 AR을 실용화한 지점이다.

### 2.3 Native Chain-of-Thought (핵심 기여 2)

기존 방법들은 sub-task나 bbox 예측 같은 auxiliary VQA를 **co-train**하지만, 이 목적함수들은 학습 시 supervision으로만 취급되고 **action 생성 과정에 명시적으로 참여하지 않는다**. 그래서 중간 추론이 실제로 downstream action 예측에 도움이 되는지 직접 평가하기 어렵다.

G0.5는 4개의 self-describing target을 action stream에 native CoT로 통합한다:

| Target | 접두어 | 역할 |
|--------|--------|------|
| Task decomposition | `Subtask:` | atomic subtask 텍스트 분해 |
| Key-object localization | `BBox:` | 과제 관련 물체 bounding box |
| Motion planning | `Trace:` | 2D end-effector 궤적 (TraceVLA 영감) |
| Action hints | `ActionHint:` | 행동 힌트 텍스트 |

각 step에서 이 target의 **임의 부분집합**을 emit할 수 있고, 학습 시 8개 curated 조합(no-CoT baseline 포함)에서 weighted random sampling으로 하나를 뽑아 **동일한 next-token 목적함수**로 지도한다. subtask-text 포맷에 더 높은 sampling weight를 준다.

**중요**: 이들은 prompt-conditional 템플릿으로 노출되므로, **재학습 없이 추론 시점에 CoT 모드를 전환**할 수 있다. 5.6절의 zero-shot probe가 정확히 이것을 이용한다.

> ❓ **예상 질문**: ECoT, CoT-VLA와의 차이는?
> **답변**: 정신적으로 ECoT에 가장 가깝다(추론과 행동이 단일 AR 디코더 공유). 차이는 두 축이다. (1) 네 가지 reasoning primitive를 **하나의 공유 토큰 vocabulary**로 결합, (2) prompt-conditional 템플릿으로 노출해 추론 시 전환 가능. CoT-VLA/DualCoT-VLA는 VLM-as-encoder backbone에 추론 모듈을 **부착**하는 방식이라, CoT 토큰이 디코더·컨텍스트·목적함수를 action 토큰과 공유하지 않는다.

### 2.4 Visual Memory (핵심 기여 3)

복잡한 mobile manipulation은 본질적으로 **non-Markovian**이다. 단일 프레임에 의존하면 로봇 팔이나 환경 clutter에 의한 일시적 occlusion에서 실패하고, 실패를 인지하고 대안적 재시도 전략을 세울 시간적 맥락이 없다.

그런데 역사적 vision token을 순진하게 stacking하면: 계산 비용이 **quadratic**으로 증가해 고주파 제어에 용납 불가한 지연이 생기고, 미지의 temporal trajectory에서 error accumulation과 state drifting에 취약해진다.

**해법** (π0.7, MEM 계열):
- ViT 내부 **4개 layer마다** factorized spatial/temporal attention 모듈 삽입 — 시간축과 spatial patch를 순차적으로 mixing하는 separable 메커니즘
- 지연을 엄격히 bound하기 위해 **마지막 layer에서 모든 historical token을 폐기**
- 학습 시 historical frame을 **stochastic drop**하여 overfitting 방지
- discrete text tokenizer를 **continuous state embedding**으로 대체해 proprioceptive 입력을 해당 시각 프레임과 정확히 동기화

> ❓ **예상 질문**: 메모리가 몇 초 수준인데 long-horizon에 충분한가?
> **답변**: 저자들 스스로 한계로 인정한다 (6절). "우리의 visual memory는 수 초의 history만 포착하며, long-horizon memory는 열린 연구 문제로 남는다."

## 3. 사전학습 (Pre-training)

**단일 스테이지**로 로봇 시연 + web-scale vision-language 데이터의 이종 혼합에 대해 학습.

- **로봇 데이터**: **14개 embodiment**, 실제 및 시뮬레이션 ontology 전반. **DROID는 foundation pre-training 혼합에 포함되지 않음** (5.1절 평가를 위해 사후 post-training).
- **전처리**: embodiment별 개별 처리. action normalization 모드(tail clipping z-score 또는 q01/q99 quantile scaling)와 per-channel action filter를 mixture 전역이 아닌 **소스별**로 설정.
- **개념 분포** (Fig. 4): action verb와 object noun 모두 명확한 **long-tail**. 고빈도 동작은 pick/place/move/put에 집중, 물체 vocabulary는 일반 가정·탁상 개체에 집중.

### Autolabeling 파이프라인
- **언어**: rule-based temporal segmentation으로 후보 action segment와 keyframe 식별 → Gemini 3, Doubao Seed 2.0 Pro 등 multimodal API로 action hint / atomic task description / episode-level instruction 생성
- **시각 grounding**: multimodal foundation model + **SAM3 tracking**으로 per-frame bbox 및 segmentation mask
- **2D trace**: robot joint pose에서 forward kinematics로 bimanual end-effector 위치 계산 후 head-camera 이미지 평면에 투영

### Web/VQA co-training
generic web VQA + embodied VQA + 자체 annotation(subtask 분해, bbox, 로봇 장면 commonsense VQA)을 **action-heavy mixture**로 결합. 두 샘플 타입 모두 동일한 next-token cross-entropy로 최적화되므로, 언어 답변·CoT trace·action code가 전부 통합 AR 디코더 안에서 지도된다.

**Optimizer**: AdamW, warmup → constant → 최종 cosine decay. **vision tower는 전 구간 unfrozen**. 평가는 고정된 **no-CoT 포맷**을 사용.

### 5.2 BEHAVIOR-1K Challenge 2025 (Table 4)

50개 full-length 가정 태스크, 10 instance씩. 랭킹 지표는 **Task Success Score** (BDDL goal predicate 완료 비율의 부분 점수).

| Method | Task Success Score |
|--------|--------------------|
| RLC (1st place, 체크포인트 4개) | 0.2605 |
| Comet (2nd place) | 0.1830 |
| π0.5 (4 epoch) | 0.2626 |
| **G0.5 (1 epoch)** | **0.2904** |
| **G0.5 (4 epoch)** | **0.3136** |

**핵심**: G0.5는 **단일 체크포인트**로 50개 태스크 전체를 커버한다. 1 epoch만으로 4 epoch π0.5를 +10.6%, 4개 체크포인트를 쓴 우승 솔루션을 +11.5% 능가. 4 epoch에서는 각각 +19.4%, +20.4%.

저자 해석: structured tokenization이 action space를 독립 motion part(left/right control, lower body)로 분해하므로 **navigation과 manipulation이 토큰 공간에서 명시적으로 분리**된다. 실제로 navigation+manipulation이 교차하는 태스크에서 강점 — moving boxes to storage (+0.35 vs π0.5), picking up trash (+0.30), loading the car (+0.28).

### 5.3 DROID 환경·물체 수준 zero-shot (Fig. 6)

DROID post-training 후, **평가 환경과 물체 인스턴스가 사전학습·post-training 어디에도 없는** Franka Research 3 셋업에 배치. 10개 태스크 × 10 trial.

- **G0.5: 82.5%**
- π0.5-DROID: 57.5% (−25.0pp)
- MolmoAct2-DROID: 52.0% (−30.5pp)

G0.5는 **10개 태스크 전부**에서 π0.5-DROID를 능가. 특히 색상 조건부 타깃 선택, 다단계 추론 태스크에서 격차가 크다. MolmoAct2-DROID는 순차 태스크(block→drawer+close)에서 완전 실패하는 반면 G0.5는 절반 이상 성공.

| GR00T-N1.7 | 24.4% | 68.9 |

6개 중 5개에서 1위. 유일한 예외는 R1-Pro box transfer & stacking (π0.5 93.3% vs G0.5 80.0%, 단 process score는 148.0 vs 142.5로 근접).

embodiment 간 균형도 양호: R1-Pro 75.6% / R1-Lite 77.8%.

### 5.5 Pick-and-Place Benchmark (PP Bench, Fig. 10)

R1-Lite로 수집한 50시간 탁상 데이터. 장면당 16개 물체 무작위 배치, 64개 물체 카테고리 + 3개 컨테이너 카테고리, OOD 16 카테고리 포함. **language following rate**와 **task success rate**를 분리 보고하는 것이 설계 요점 — 실패가 잘못된 물체를 잡은 것인지, 올바른 타깃 선택 후 저수준 실행 오류인지 구분한다.

| Post-training | G0.5 LF / TS | π0.5 LF / TS |
|---------------|--------------|--------------|
| Zero-shot | **65.6% / 59.4%** | 0.0% / 0.0% |
| 1H | 62.5% / 57.8% | 21.9% / 3.1% |
| 10H | 71.9% / 65.6% | 56.3% / 42.2% |
| 50H | **84.4% / 75.0%** | 68.8% / 65.6% |

**가장 인상적인 수치**: G0.5의 **zero-shot** language following(65.6%)이 π0.5의 **50H post-trained** 수치(68.8%)에 근접하고, task success에서는 zero-shot 59.4%가 π0.5의 10H(42.2%)를 크게 상회한다.

**Referring context ablation** (Table 5):

| Metric | Name-only | + Box Coord. | + Target Visual |
|--------|-----------|--------------|-----------------|
| Language Following | 84.4% | 85.9% | **98.4%** |
| Task Success | 75.0% | 76.6% | **84.4%** |

좌표 토큰 추가는 **거의 효과 없음**(+1.5pp). 저자 가설: 좌표 토큰 직접 주입이 name-only 로봇 사전학습 분포로부터 instruction-format shift를 유발하고, post-training 데이터가 action head가 이 새 conditioning 신호를 안정적으로 활용하기에 불충분. 반면 **타깃의 crop된 시각 영역**을 추가 뷰로 붙이면 LF가 98.4%로 급등 — "말"이라 라벨링된 중국 장기말처럼 언어만으로 구분하기 어려운 long-tail 카테고리에 특히 유효.

### 5.6 CoT × Action Head zero-shot probe (Fig. 11)

**단일 사전학습 체크포인트**, 추론 시 설정만 토글. PP Bench(단일 stage) + 신규 long-horizon zero-shot 태스크 2개(Air Fryer, Cook Bacon; 각 5단계).

**Finding 1 — CoT는 long-horizon stage-conditioned rollout에서만 이득**: 단일 stage PP Bench에서 CoT 효과는 사실상 없음 (AR 65.6→67.2, FM 59.4→60.9, 최대 ~1.6pp). rollout당 grounding 이벤트가 하나뿐이라 단계별 추론이 기여할 여지가 없다.

**Finding 2 — AR이 FM보다 CoT를 더 충실히 따른다**: matched CoT 조건에서

| Task | AR (no CoT → CoT) | FM (no CoT → CoT) |
|------|-------------------|-------------------|
| Air Fryer progress (0-5) | 2.4 → **3.8** | 2.1 → 2.7 |
| Bacon progress (0-5) | 1.5 → **3.4** | 1.2 → 2.0 |
| Air Fryer LF rate | **72** | 48 |
| Bacon LF rate | **64** | 44 |

**CoT 품질 자체는 동등**하다 — 저자들이 CoT-on rollout의 subtask 텍스트와 bbox 정확도를 수동 채점한 결과 PP Bench ~90%, Air Fryer ~85%, Bacon ~80%로 AR-FM 간 체계적 차이 없음. 따라서 격차의 원인은 추론 내용이 아니라 **디코딩 인터페이스**라는 가설: AR action token은 CoT와 같은 stream에서 emit되어 **직접 attend**할 수 있는 반면, FM head는 hidden state의 **pooled summary**에 조건화된다.

### 5.7 RL 적합성 (Fig. 12)

AR 정책은 action을 토큰으로 emit하므로 **정확한 token-level log-probability**를 노출한다 — ratio 기반 RL 알고리즘이 소비하는 바로 그 양이다. FM head에는 그런 likelihood가 없어 재정식화가 필요하다.

LIBERO에서 태스크당 **시연 1개**로 AR/FM 정책을 공동 post-training한 뒤, 초기 성공률이 비슷한 4개 태스크를 골라 GRPO 적용. FM 쪽은 denoising 절차에 SDE를 도입하고 denoising trajectory를 Markov process로 취급해 log-probability를 근사(RLinf 방식).

결과: **AR이 실질적으로 더 빨리 수렴하고, 더 높은 최종 성공률에 도달하며, 분산이 낮아 더 안정적으로 학습된다.**

### 5.8 추론 지연 (Fig. 1)

FlashRT 기준: **FM 190 ms / AR w/ CoT 192 ms / AR w/o CoT 130 ms**. 즉 "AR은 느리다"는 통념과 달리 **디코딩은 병목이 아니다** — CoT를 켜도 FM과 동등하고, 끄면 오히려 빠르다.

## 6. 강점

1. **논지와 증거의 일관성**: "VLM을 actor로 되돌리자"는 주장을 7개 독립 regime에서 검증했고, 그중 다수가 실기다. 시뮬 벤치마크만으로 논지를 세우지 않았다.
2. **5.6절의 controlled probe 설계**: 단일 체크포인트에서 추론 시점 설정만 토글하는 방식은 AR vs FM 비교에서 파라미터·데이터·학습 예산 교란을 원천 차단한다. 이 분야에서 보기 드물게 깔끔한 ablation이다.
3. **CoT 품질 자체를 수동 채점**해 성능 격차의 원인을 "추론 내용"이 아니라 "디코딩 인터페이스"로 좁힌 것.
4. **BEHAVIOR 단일 체크포인트 결과**: 4개 체크포인트를 쓴 챌린지 우승 솔루션을 1 epoch 단일 체크포인트로 이겼다는 것은 사전학습 표현의 일반성을 강하게 시사한다.
5. **PP Bench의 language following / task success 분리**: 실패 원인을 grounding과 execution으로 나눠 보고하는 설계는 다른 실기 벤치마크가 따라야 할 관행이다.
6. **RL 친화성**: token log-probability가 곧바로 GRPO에 들어간다는 점은 아키텍처 선택의 downstream 파급을 보여주는 설득력 있는 논거다.

## 7. 약점 및 한계

1. **저자가 인정한 실패 모드**:
   - Drawer-insertion과 반투명 캐비닛 태스크가 G0.5의 두 변형 모두에서 취약. AR로 닫히지 않는 **센싱 한계**를 시사.
   - Visual memory가 수 초 history만 포착 — long-horizon memory는 미해결.
   - Lower-body 구동이 통합 action space에 표현되어 있으나 **별도로 평가되지 않음**.
2. **DROID drawer 실험의 함의**: 고대비 마커 없이는 G0.5-DROID 60% vs π0.5-DROID 90%로 **역전**된다. 마커를 붙이면 100%로 급등. 즉 G0.5는 저대비 반투명 표면에서 명시적 시각 단서 없이 타깃을 localize하는 능력이 상대적으로 부족하다. 논문은 이를 정직하게 보고하지만, 주 결과(82.5%)는 마커가 있는 조건이다.
3. **Prompt-level steerability는 정성 관찰에 머문다**: "push it in hard", "vertically" 같은 부사·공간 수식어가 rollout을 바꾼다는 관찰은 흥미롭지만 저자들도 "small set"에서의 비정형 관찰이라고 명시. 체계적 연구를 future work로 넘겼다.
4. **Long-horizon zero-shot probe의 표본 크기**: Air Fryer / Bacon은 셀당 **n=5 rollout**. Finding 2의 progress score 차이(2.4→3.8 vs 2.1→2.7)는 방향성은 일관되나 통계적 강건성은 제한적이다.
5. **Ablation 부재 영역**: RVQ의 residual round 수 R, temporal contrastive objective의 기여도, visual memory 삽입 간격(4 layer마다)에 대한 정량 ablation이 제시되지 않는다. 세 구성요소 각각의 기여를 분리하기 어렵다.
6. **파라미터 스케일**: 2B backbone 하나만 평가되어 AR의 이점이 스케일에 따라 어떻게 변하는지 알 수 없다. AR이 FM 대비 "더 잘 학습된다"는 주장의 스케일링 법칙은 미검증.
7. **비교 대상의 이질성**: BEHAVIOR 표에서 RLC/Comet은 공개 리더보드 제출(다중 정책)이고 π0.5와 G0.5만 저자들이 직접 평가했다. 논문이 이를 명시하긴 하나 표의 숫자를 나란히 읽을 때 주의가 필요하다.

## 10. 재현/확장 아이디어

1. **Scaling study**: 동일 레시피를 0.5B / 2B / 7B / 14B backbone에 적용해 "AR > FM" 격차가 스케일에 따라 벌어지는지 좁혀지는지 확인. 논문의 핵심 주장을 검증할 가장 직접적인 후속.
2. **Codec ablation**: temporal contrastive objective를 제거하고 Hamming distance 일관성 지표와 downstream 성능을 측정. 저자가 지적한 "(b) 토큰 일관성" 문제의 실제 크기를 정량화.
3. **Active-part tokenization의 효율 측정**: bimanual 태스크에서 실제 토큰 절감률과 latency 개선을 embodiment별로 보고. 현재는 개념적 주장에 머문다.
4. **CoT primitive별 기여도 분해**: 8개 curated 조합을 개별 primitive 단위로 쪼개 long-horizon 태스크에서 어느 primitive가 progress score를 올리는지 측정. Trace vs BBox vs Subtask의 상대적 가치는 아직 미지.
5. **저대비 센싱 보강**: DROID drawer 실패 모드를 깊이 센서, 편광 이미징, 또는 명시적 aperture detection head로 보완. 논문이 "AR로 닫히지 않는 한계"라 명시한 지점.
6. **Long-term memory 확장**: 현재 수 초 → episodic memory 또는 외부 retrieval로 확장. BEHAVIOR처럼 에피소드 평균 6.6분인 태스크에서 이득이 클 것.
7. **RL 스케일업**: GRPO를 4개 LIBERO 태스크가 아닌 전체 suite 또는 실기로 확장. AR의 RL 친화성이 논문의 가장 실용적 함의인데 검증 규모가 작다.
8. **Prompt steerability 정량화**: 부사·공간 수식어·동의 동사 치환에 대한 체계적 프로토콜을 만들어 zero-shot 행동 제어 가능성을 측정. 저자들이 명시적으로 요청한 후속 연구.

## 11. 세미나 토론 포인트

1. **"VLM을 actor로 되돌린다"는 주장은 아키텍처 논쟁인가, tokenizer 논쟁인가?** G0.5의 이득 중 얼마가 AR 자체에서 오고 얼마가 학습형 cross-embodiment codec에서 오는가? FM head에 동일한 codec 기반 표현을 조건화하면 격차가 유지되는가?

2. **5.6절 probe가 정말 "디코딩 인터페이스"를 격리하는가?** FM head는 사전학습 전 구간에서 주 목적함수로 학습되지 않고 AR trunk에 부착된 부속물이다. 이 비대칭이 FM에 불리하게 작용했을 가능성은?

3. **CoT 이득이 long-horizon에서만 나타난다는 발견의 함의**: 단일 stage에서 ~1.6pp에 불과하다면, CoT의 가치는 "추론"이 아니라 "단계별 재-grounding 기회"에 있는 것 아닌가? 그렇다면 CoT 없이 단순히 stage마다 re-prompt하는 것과 어떻게 다른가?

4. **Referring context 결과의 역설**: 좌표 토큰(+1.5pp)보다 crop 이미지(+14pp)가 압도적으로 유용하다는 것은, 통합 토큰 stream을 자랑하는 모델이 정작 **텍스트 좌표를 활용하지 못한다**는 뜻이다. "one autoregressive stream" 서사와 긴장 관계에 있지 않은가?

5. **DROID 마커 실험을 어떻게 볼 것인가?** 마커 유무로 60% ↔ 100%가 갈리고, 마커 없을 때는 π0.5(90%)에 크게 진다. 주 결과 82.5%의 일반화 주장을 어느 정도 할인해야 하는가?

6. **27차원 통합 action space + noop token 전략의 한계**: 손가락이 많은 dexterous hand나 사족보행처럼 이 partition에 맞지 않는 형태는? per-robot adapter 없는 설계가 어디까지 확장되는가?

7. **BEHAVIOR 단일 체크포인트 vs 4 체크포인트 비교의 공정성**: 우승 솔루션이 태스크 분포별 체크포인트를 고른 것은 리더보드 규칙 안에서의 최적화다. "단일 체크포인트로 이겼다"는 주장이 아키텍처 우위인가, 평가 프로토콜 차이인가?

8. **RL 결과를 얼마나 신뢰할 것인가?** FM 쪽 log-probability 근사(SDE + Markov 가정)가 불리하게 설정되었을 여지는? "AR이 RL-native"라는 주장은 원리적으로 타당해 보이지만, 비교 실험이 그것을 증명하는가?

## 12. 총평

G0.5는 **잘 조준된 반박 논문**이다. 필드가 VLM-as-encoder + flow-matching expert로 수렴하는 흐름에 대해, 그 전환의 원인이었던 병목(action token 폭증)만 정확히 제거하면 AR이 여전히, 그리고 여러 축에서 **더** 낫다는 것을 보인다.

가장 설득력 있는 부분은 벤치마크 수치가 아니라 **논증의 구조**다. 저자들은 세 가지 서로 다른 종류의 증거를 제시한다: (1) 성능 — 7개 regime SOTA, (2) 학습 동역학 — 동일 조건에서 AR이 더 빨리, 더 좋은 optimum으로 수렴하고 RL에 직결됨, (3) 메커니즘 — 단일 체크포인트 probe로 CoT 활용도 격차가 추론 품질이 아닌 디코딩 인터페이스에서 온다는 것을 격리. 특히 (3)은 "AR이 이겼다"를 넘어 **왜** 이기는지에 대한 인과적 설명을 시도하며, 이런 수준의 controlled ablation은 이 분야에서 드물다.

동시에 이 논문은 자신의 한계에 대해 이례적으로 정직하다. Drawer 마커 실험처럼 자기 모델이 지는 조건을 굳이 보고하고, prompt steerability를 "정성 관찰"이라 명확히 한정하며, lower-body가 평가되지 않았음을 명시한다.

남는 불확실성은 두 가지다. 첫째, **2B 하나만 평가**되어 AR 우위의 스케일링 거동을 알 수 없다. 둘째, 실기 증거의 다수가 **Galaxea 자체 하드웨어와 자체 벤치마크**에 묶여 있어 독립 검증 가능한 표면적이 좁다. 사전학습 backbone이 공개된다면 이 두 문제 모두 커뮤니티가 풀 수 있는 형태가 된다.

**결론적으로**, 별도 action expert를 정교하게 설계하는 방향과, backbone 자체를 강화해 그것이 직접 행동하게 하는 방향 사이에서 후자를 택할 이유를 이 논문은 상당히 강하게 제시한다. 최소한 "flow-matching expert는 이제 기본값"이라는 가정은 재검토되어야 한다.
