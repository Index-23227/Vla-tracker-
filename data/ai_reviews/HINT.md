# HINT — Human-Intent Inception for Long-Horizon Robot Manipulation

- arXiv: 2609.02653 (v1 2026-09-02, v2 2026-09-06)
- 소속: Zhejiang University, Shanghai Jiao Tong University, Noematrix, EndlessAI (Mingyu Mei, Haojie Xu 외, 교신 Zaixing He)

## 1. 한 줄 요약

HINT는 "의미적 의도는 조작 패턴이 바뀔 때만 드물게 바뀌고, 연속 제어는 손-물체 관계에 의존한다"는 인간 조작 원리에 따라, 패턴 전환 시점에만 VLM으로 하위 과제와 목표를 정하고 그 사이에는 SAM2로 목표를 추적하며, 추적된 목표를 이미지 하이라이트와 어텐션 편향으로 정책에 주입하는 에이전트형 프레임워크다. 하이라이트 입력으로 미세조정한 π0.5 + HINT는 실세계 세 장기 과제의 Full SR을 10/13.3/5% → 60/86.7/40%로 올린다.

## 2. 문제 설정

VLA는 희소한 언어 지시와 조밀하게 변하는 시각 입력 사이에서 시각적 상관(예: 블록 색)을 따라가는 **visual shortcut**에 빠져, 무엇을 조작해야 하는지(what)를 자주 놓친다. 논문의 "easy vs mixed" 분류 실험에서 π0.5는 고정 매핑(easy)일 때 Sub. SR 89.5%지만, 지시에 따라 매핑이 바뀌는 mixed 설정에서는 52.2%로 거의 찍기 수준이 된다. 매 프레임 VLM 추론을 돌리면 지연이 커진다는 점도 문제다.

## 3. 핵심 아이디어

"which/when → what/where → how"로 나눈다. (1) 패턴 라우터가 현재 조작 패턴을 보고 어느 뷰를 우선할지와 언제 의미 추론을 다시 할지 정하고, (2) 전환 시점에만 과제 관리자가 하위 과제·목표를 확정한 뒤 추적으로 유지하며, (3) 목표를 정책이 이미 쓰는 시각 채널로 전달한다. 정책은 "어떻게" 움직일지만 맡는다.

## 4. 아키텍처

- **Pattern Router**: 전역·양 손목 뷰(ResNet-18 공유 + 뷰별 어댑터), 고유수용·관절 토크(각각 GRU)를 게이트 융합해 4개 패턴(free move / pre-contact / transport contact / dexterous contact)과 패턴 내 진행도를 예측. 손실은 CE + 0.5·MSE.
- **Task Manager**(Qwen3-VL): 초기 하위 과제 계획을 세우고, 패턴 전환마다 활성 하위 과제 ℓ_k와 목표 o*_k를 갱신.
- **Semantic Grounder**: Grounding DINO(단순 객체) 또는 Qwen(속성·공간 관계)으로 라우팅된 뷰에서 목표 bbox와 신뢰도 산출.
- **Goal-consistent tracking**: SAM2로 목표 마스크를 추적하고 신뢰도가 낮으면 같은 목표로 재그라운딩.
- **Intent injection**: (a) 라우팅된 뷰에만 마스크를 반투명(불투명도 0.32) 녹색으로 칠하고 윤곽선 표시, (b) 패치별 목표 점유율을 비전 인코더 self-attention과 action-to-vision attention 로짓에 더하는 head 공유 편향(중간 층 위주로 주입). 액션 모델에 학습 파라미터를 추가하지 않는다.

## 5. 학습과 추론

정책 학습 시 관측을 정답 패턴·목표 주석으로 오프라인 렌더링(하이라이트 + 어텐션 prior)하여 π0.5(또는 Wall-OSS-0.5)를 미세조정하고, 배포 시에는 같은 렌더링을 온라인 그라운딩·추적 마스크로 수행한다(train-test 대칭). 베이스라인과 HINT 변형은 같은 시연·최적화·초기화를 공유한다. π0.5는 AdamW, LR 2e-5 → 2e-7, 배치 32, 과제별 50k/80k/80k step. 데이터는 AgileX PiPER 양팔로 30 Hz 텔레오퍼레이션한 50/80/150개 시연.

## 6. 주요 결과 — 분포 내(Table I)

| 방법 | 정렬 IS/Sub/Full | 스펠링 IS/Sub/Full | 페그 IS/Sub/Full |
|---|---|---|---|
| Wall-OSS-0.5 | 53.1 / 53.1 / 0.0 | 44.7 / 36.2 / 13.3 | 65.0 / 25.0 / 5.0 |
| π0.5 | 52.2 / 52.2 / 10.0 | 44.7 / 42.6 / 13.3 | 35.0 / 27.5 / 5.0 |
| Wall-OSS-0.5 + HINT | 85.8 / 85.8 / 40.0 | 83.0 / 80.9 / 40.0 | 86.7 / 47.5 / 10.0 |
| **π0.5 + HINT** | **91.2 / 91.2 / 60.0** | **97.9 / 95.7 / 86.7** | **100.0 / 67.5 / 40.0** |

정렬·페그는 20회, 스펠링은 15회 시행이며 스펠링·페그의 Full SR에는 0.5 부분 점수가 있다. 페그에서 IS 100%인데 Full SR 40%에 그치는 것은 남은 병목이 접촉 정밀 제어(액션 측)임을 보여준다.

## 7. 분포 외 일반화(Table II)와 라우팅·지연

- OOD(새 물체·배치·색·단어·공간 지시, 10회): π0.5 + HINT는 IS 82.6/95.5/90.0, Sub. SR 80.4/87.5/55.0, Full SR 세 과제 모두 30.0(π0.5는 모두 0.0). Wall-OSS + HINT Full SR은 20/20/10.
- 패턴 라우터: 평균 Pattern SR ID 94.7% → OOD 91.1%, 페그는 90.6% / 86.1%. 하위 과제 전환은 260회 중 251회 성공.
- 지연(Table III): π0.5 185 ms, 라우터 14 ms, SAM2 43 ms, Qwen 추론 프레임 630 ms, 추적 프레임 242 ms. 추적으로 보조 오버헤드가 445 ms에서 57 ms로 준다.

## 8. 어블레이션 (Table IV, Fig. 8)

OOD 스펠링에서 하이라이트 제거 시 IS/Sub/Full = 59.1/58.0/10.0, 어텐션 제거 시 88.6/73.9/10.0, 완전한 HINT는 95.5/87.5/30.0. 하이라이트는 색 등 외관 변이를 정규화해 의도 고정에 크게 기여하고, 어텐션은 정밀 파지에 기여한다. 연속 추적은 하위 과제·전체 완료 시간을 25.3%·21.5% 줄이고, 손목 뷰는 Sub. SR 80.7 → 87.5, Full SR 10 → 30으로 올린다.

## 9. 설계 해석

"무엇"을 모델 파라미터로 배우게 하지 않고 입력 채널에 명시함으로써, VLM의 의미 일반화 능력을 정책의 모터 능력과 느슨하게 결합했다. 학습 시에도 같은 하이라이트 입력을 쓰므로 정책이 "칠해진 물체를 조작하라"는 대상 불변 규칙을 배우게 되고, 이것이 OOD에서 새 색·새 글자로 옮겨가는 근거다. 패턴 기반 스케줄링은 비싼 추론을 의미가 바뀌는 순간에만 쓰는 이벤트 인터페이스 역할을 한다.

## 10. 강점

- 두 가지 파운데이션 정책(π0.5, Wall-OSS-0.5)에서 일관된 대폭 향상.
- 액션 모델에 학습 파라미터를 추가하지 않는 백본 불문 인터페이스.
- 패턴 전환 기반 추론 호출로 지연을 억제하고 모듈별 지연을 투명하게 보고.
- 시각적 지름길 현상을 easy/mixed 대조로 명확하게 드러냄.

## 11. 한계

- 과제 3개, 단일 양팔 플랫폼, 시행 수 10–20회로 규모가 작고 시뮬레이션 표준 벤치마크가 없다.
- 패턴 라우터 학습에 수동 패턴 주석, 정책 학습에 하이라이트·어텐션 prior 전처리 파이프라인이 필요하다.
- OneTwoVLA, VP-VLA 등 다른 추론·그라운딩 방법과의 정량 비교가 없다.
- 의미 일반화는 VLM의 사전 지식에 의존하며, 접촉 정밀 제어 문제는 해결하지 않는다(페그 Full SR 40%).

## 12. VLA-Tracker 관점 평가

외부 모듈이 많은 에이전트형 프레임워크지만, 하이라이트·어텐션 prior가 들어간 관측으로 π0.5와 Wall-OSS-0.5를 직접 미세조정하고 패턴 라우터도 학습하므로 동결 정책 위의 래퍼가 아닌 자체 학습 정책으로 보고 수록한다. 표준 추적 벤치마크 결과는 없다. `real_world`에는 π0.5 + HINT의 분포 내 과제별 Full SR만 두었고(논문이 절대 평균을 보고하지 않아 avg는 선언하지 않음), IS/Sub. SR, OOD, Wall-OSS 변형, 베이스라인, 어블레이션, 라우터 신뢰도, 지연은 모두 별도 블록으로 분리했다.
