# MA-VLA — Multi-Arm Vision-Language-Action Model for Collaboration and Compositional Generalization

- arXiv: 2608.25864 (2026-08-26)
- 소속: 대련이공대학교, 옥스퍼드 대학교, 중산대학교, 상하이교통대학교, 중국과학기술대학교, 홍콩중문대학교(선전), 베이항대학교
- 코드: https://github.com/zhangzaibin/future-robots

## 1. 한 줄 요약

MA-VLA는 고수준 지시를 팔별 "원자 행동(atomic prompt)"으로 나누어 할당하는 다중 팔(2–4개) VLA다. 실행기는 π0(pi0_base)를 파인튜닝한 것이고, 계획기는 파인튜닝하지 않은 GPT-4.1이다. 학습 중 팔의 (상태, 손목 시점, 원자 프롬프트, 행동) 묶음을 무작위로 섞는 **Arm Shuffle**로 팔 번호와 역할의 결속을 끊는다. 그 결과 학습에 없던 협업 패턴에서 기존 VLA는 모두 0%인데 MA-VLA는 평균 13.0%를 기록했다. RoboTwin 2.0 Hard 7개 과제 평균은 49.0%(π0 41.1%)다.

## 2. 문제 설정

기존 VLA는 언어를 하나의 전역 명령으로 취급해 "어느 팔이 무엇을 할지"를 데이터에서 암묵적으로 배우게 한다. 그러면 분업이 학습 때 본 몇 가지 협업 패턴에 과적합된다. 저자들은 **다중 팔 조합 일반화(multi-arm compositional generalization)**라는 설정을 정의한다. 원자 행동 집합은 학습과 같게 두고(U_test = U_train), 이들을 조합한 협업 구조만 바꾼다(P_test ⊄ P_train). 달라지는 것은 팔 역할 배정, 순서와 동기화, 그로 인한 중간 상태다. 예를 들어 큐브 쌓기 순서를 바꾸거나 물건 전달 방향을 뒤집는다.

## 3. 핵심 아이디어

- **원자 행동 할당**: 지시를 단계별 팔별 원자 프롬프트(grasp, hold bowl, place cube 등 유한 템플릿 집합)로 분해해 분업을 명시적으로 만든다.
- **단일 통합 실행기**: 모든 팔의 프롬프트를 "Arm0: p0, Arm1: p1, ..." 한 문자열로 이어 붙여 하나의 VLA가 모든 팔의 행동을 한 번에 예측한다. 팔마다 별도 모델을 두지 않는다.
- **Arm Shuffle과 View Dropout**: 학습 전용 데이터 교란으로, 역할 불변적 지시 따르기와 중복 시점 활용을 유도한다.

## 4. 방법 상세

- **VLM 계획기 P_φ**: 지시 l, 이미지 집합 I, 원자 프롬프트 집합 A를 받아 전체 프롬프트 시퀀스 (p_1, ..., p_T)를 한 번의 순전파로 생성한다. GPT-4.1에 템플릿을 고르도록 프롬프트하고 출력은 A의 유효 템플릿으로 정규화한다. 계획기는 파인튜닝하지 않는다.
- **VLA 실행기 π_θ**: 전역·손목 다시점 이미지, 모든 팔의 고유수용 상태, 통합 프롬프트 u_t를 받아 [a^1_t, ..., a^N_t]를 출력한다. π0 방식의 flow-matching으로 행동을 생성하고, 공유 잠재 표현을 팔별 행동 헤드로 나누는 multi-head projection 층을 추가했다.
- **Arm Shuffle**: 확률 p_shuffle로 팔 인덱스의 무작위 순열 σ를 뽑아 (s^i, v^i, p^i, a^i) → (s^σ(i), v^σ(i), p^σ(i), a^σ(i))로 바꾼다. 모델은 위치나 번호가 아니라 프롬프트의 의미로 행동을 결정해야 한다.
- **View Dropout**: 확률 p_drop으로 일부 카메라 시점을 0으로 가린다.
- **손실**: 두 교란을 적용한 입력에 대해 팔별 BC 손실을 합한다. 목적 함수 자체는 바뀌지 않는다.
- **원자 라벨**: 접촉, 파지 상태, 물체 자세 임계값 같은 과제별 상태 술어를 쓰는 규칙 기반 파서로 시연을 프레임 단위 원자 프롬프트로 변환한다.

## 5. 학습 설정

- 시뮬레이션 과제당 전문가 시연 150개, SO101 실로봇 과제당 LeRobot 원격조작 시연 50개.
- A800 GPU 2장, 배치 32, horizon 50. RoboFactory 2팔 과제 10k 스텝, 3–4팔 과제 15k 스텝, RoboTwin 2.0 Hard 30k 스텝, SO101 15k 스텝.
- OOD 과제별 교란 확률: Three Robots Stack Cube p_shuffle=0.8/p_drop=0.2, Pass Two Shoes 1.0/0.4, Reverse Stack Bowls 0.6/0.4. SO101은 1.0/0.4.
- 베이스라인(ACT, DP, DP3, π0-FAST, π0)도 같은 시연과 같은 학습 예산으로 재학습했다. 단일 팔용 입출력은 다중 팔용으로 개조했다.

## 6. 실험 설정

- **RoboFactory**: 2–4팔 협업 과제. 2팔(Lift Barrier, Place Food, Stack Cube, Pass Shoe), 3팔(Stack Cube, Camera Alignment), 4팔(Long Pipeline Delivery, Take Photo).
- **RoboTwin 2.0 (Hard)**: 방해물, 배경, 조명 변화가 강한 양팔 과제 중 7개를 골랐다.
- **실로봇**: 양팔 SO101(팔당 6-DoF), 전역 카메라 1대 + 손목 카메라 2대, 30 Hz. 과제당 20 에피소드.
- 시뮬레이션은 구성마다 100회 롤아웃의 평균 성공률을 보고한다.

## 7. 인도메인 결과 (Table 1, 2)

| RoboFactory | DP | π0-FAST | π0 | MA-VLA |
|---|---|---|---|---|
| 2팔 평균 | 27.5 | 57.5 | 80.3 | **83.5** |
| 3–4팔 평균 | 15.3 | 11.8 | 76.5 | **83.3** |

3–4팔 과제에서 향상 폭이 크다. Long Pipeline Delivery는 π0 82.0% → 97.0%, Three Arms Stack Cube는 48.0% → 58.0%다. Take Photo는 두 모델 모두 82.0%로 같다.

| RoboTwin 2.0 Hard | ACT | DP | DP3 | π0-FAST | π0 | MA-VLA |
|---|---|---|---|---|---|---|
| 7개 과제 평균 | 12.3 | 18.9 | 28.6 | 27.0 | 41.1 | **49.0** |

과제별로는 Handover Block 27 → 46, Place Object (Cabinet) 59 → 71, Stamp Seal 3 → 12로 오르는 등 7개 과제 모두 π0 이상이다.

## 8. 조합 일반화와 실로봇 결과 (Table 3, 4)

- **시뮬레이션 OOD(Table 3)**: 큐브 쌓기 순서 GBR/RGB/BRG, Pass Two Shoes, Stack Two Bowls에서 DP, π0-FAST, π0는 모든 열이 0.0이다. MA-VLA는 28.0 / 9.0 / 9.0 / 9.0 / 10.0, 평균 13.0이다.
- **SO101 실로봇(Table 4, 20회 중 성공 수)**:

| 과제 | π0 ID | MA-VLA ID | π0 OOD | MA-VLA OOD |
|---|---|---|---|---|
| Stack Bowls | 9 | 12 | 0 | 10 |
| Place Cubes | 12 | 15 | 0 | 8 |
| Pass Toys | 3 | 6 | 0 | 2 |
| Stack Cubes | 5 | 8 | 0 | 2 |

OOD는 쌓기·배치 순서를 뒤집거나 전달 순서를 바꾼 설정이다. π0는 4개 OOD 과제 모두 0/20이다.

## 9. 어블레이션 (Table 5, 6, Fig. 5)

- **구성 요소(Three Robots Stack Cube)**: 아무것도 없을 때 OOD 0.0 / ID 48.0 → 원자 프롬프트만 추가 0.0 / 58.0 → Arm Shuffle 추가 7.3 / 52.0 → View Dropout까지 15.3 / 53.0. 원자 프롬프트는 인도메인을 올리지만 OOD는 Arm Shuffle이 있어야 0을 벗어난다. 대신 인도메인은 58.0에서 53.0으로 떨어진다.
- **Shuffle 확률(Fig. 5)**: 0%에서 OOD가 0이고 비율을 올리면 OOD가 오른다. 그림의 수치로는 80% 부근이 가장 좋다. 이 결과는 그림에만 있다.
- **분리 모델(Table 6)**: 팔마다 π0를 따로 학습한 Separate π0(모델 3개)는 인도메인 61.0%로 가장 높지만 OOD는 0.0%다. MA-VLA는 모델 하나로 OOD 15.3 / ID 53.0, 평균 34.2(Separate 30.5)다.

## 10. 강점

- 다중 팔 조합 일반화라는 문제를 명확히 정의했고, 원자 행동은 같고 협업 구조만 바뀌는 평가 분할을 직접 만들었다.
- Arm Shuffle은 구현이 간단한 데이터 교란인데도 OOD 성공률을 0에서 끌어올린다는 것을 어블레이션으로 분명히 보여준다.
- 2팔부터 4팔까지 하나의 모델로 다루고, 팔 수가 늘수록 인도메인 이득이 커진다.
- 코드, 모델, 데이터 공개를 명시했다.

## 11. 한계

- OOD 절대 성공률이 여전히 낮다(시뮬레이션 평균 13.0%, 실로봇 Pass Toys·Stack Cubes 2/20).
- 계획기가 GPT-4.1 API다. 실행 중 원자 프롬프트의 단계 전환 조건은 부록에 미뤘고, 계획기 오류가 성능에 미치는 영향은 분석하지 않았다.
- Arm Shuffle은 인도메인 성능을 다소 낮춘다(58.0 → 52–53). 과제마다 p_shuffle과 p_drop을 따로 맞췄기 때문에 OOD 과제를 보고 하이퍼파라미터를 고른 셈이 될 수 있다.
- RoboTwin 2.0은 Hard 설정의 7개 과제만 썼으므로 전체 스위트 평균과 직접 비교할 수 없다.
- 원자 라벨을 만드는 규칙 기반 파서가 과제별 상태 술어에 의존한다. 새 과제에 확장하려면 수작업이 필요하다.
- 실로봇은 과제당 20회로 표본이 작다.

## 12. VLA-Tracker 관점 평가

MA-VLA는 π0를 파인튜닝한 자체 실행기 정책을 학습하고 정량 결과를 보고하므로 수록 기준을 충족한다. GPT-4.1 계획기는 고정이지만 핵심 기여인 Arm Shuffle과 multi-head 실행기는 학습된 정책에 있다. 트래커 표준 키로는 RoboTwin 2.0 Hard 7개 과제 평균 49.0을 robotwin_v2에 넣었다. 이는 부분 집합 평균이므로 전체 스위트 모델과 순위를 비교할 때 주의해야 한다. RoboFactory 결과, 조합 OOD, SO101 실로봇, 어블레이션은 별도 블록으로 분리했다. 다중 팔(3–4팔) VLA와 역할 불변 학습이라는 드문 축을 대표하며, TwinVLA, AnyBimanual 같은 양팔 전용 방법과 비교할 때 참고할 만하다.
