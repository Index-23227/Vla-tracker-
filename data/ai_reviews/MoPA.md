# MoPA — Coordinated Mobile Manipulation via Subsystem-Specific Perception Alignment

- arXiv: 2609.12081 (PDF 스탬프는 v2, 2026-09-14)
- 소속: THU, Xspark AI, HKUST (GZ), HKU (교신: Wenbo Ding, Renjing Xu)
- 프로젝트: https://MoPA-policy.github.io (코드 공개 여부는 논문에 명시되지 않음)

## 1. 한 줄 요약

MoPA는 모바일 매니퓰레이션에서 베이스(이동)와 팔(조작)이 서로 다른 공간 스케일의 지각 증거를 필요로 한다는 점에 주목해, 공유 Qwen3-VL 문맥에서 **상호 마스킹된 두 쿼리 뱅크(Manip/Mobile Query)** 로 서브시스템별 지각을 따로 뽑고, 구조화된 Mixture-of-Transformers 디코더에서 각 쿼리 뱅크를 대응 행동 스트림과 층마다 함께 갱신하며, 결합 조건부 flow matching으로 두 행동 청크를 동시에 생성하는 VLA 정책이다. ManiSkill-HAB 세 스위트 모두에서 최고 성능(SetTable 88.3 / TidyHouse 72.2 / PrepareGroceries 67.8)을, 실로봇 4과제 평균 76.3%(최강 베이스라인 π0.5 대비 +12.5pt)를 보고한다.

## 2. 문제 설정

기존 모바일 매니퓰레이션 정책은 서브시스템별 행동 생성(분리 헤드, 토큰 라우팅, 전문가 스트림)을 쓰더라도 이들을 공유·전역 융합 표현으로 조건화한다. 그러면 하나의 표현이 장면 레이아웃과 국소 상호작용 기하를 동시에 담아야 하고, 두 분기의 손실이 공유 투영층을 함께 갱신하며 그래디언트 충돌을 일으킬 수 있다. 저자들은 "출력 파라미터 분리만으로는 서브시스템별 지각 조건화가 보장되지 않는다"고 주장한다.

## 3. 핵심 아이디어

(1) 공유 VL 문맥에서 서브시스템별 지각 표현을 **행동 디코딩 이전에** 명시적으로 만든다(Dual Perceptual Streams). (2) 그 표현을 정적 요약으로 두지 않고 대응하는 행동 토큰과 함께 층마다 갱신하되, 두 행동 스트림끼리는 정보를 교환해 전신 협응을 유지한다(Perception2Action Adaptation). (3) 두 행동 청크를 하나의 결합 벡터장으로 학습·동기 적분한다.

## 4. 아키텍처

- **입력**: 헤드·손목 RGB, 고유수용감각 s_t, 언어 지시. 고유감각은 VLM을 우회해 각 행동 분기에서 따로 인코딩.
- **Dual Perceptual Streams**: VLM 토큰열 P_t 뒤에 Q_Manip, Q_Mob를 붙이고, 두 뱅크는 P_t에는 주의하되 서로에게는 마스킹된다. 최종 은닉 상태를 분기별 projector로 행동 모델 공간에 사상.
- **Perception2Action Adaptation**: 구조화된 MoT 디코더 L개 블록. 각 스트림(쿼리 2개 + 행동 2개)이 자체 projection·정규화·FFN을 갖고, 쿼리는 자기 행동 스트림하고만 양방향으로 연결되며 행동 스트림 둘은 서로 연결된다.
- **Coupled CFM**: 공유 flow time τ에서 두 분기의 선형 보간·속도 목표를 두고, 분기 차원 H·d_k로 정규화한 가중 손실을 쓴다. 추론 시 두 청크를 독립 가우시안에서 시작해 N=4 Euler 스텝으로 동시에 적분하며, 두 속도 모두 갱신 전 쌍에서 평가한다.

## 5. 학습과 추론

시뮬레이션: 스위트마다 정책 하나, 스킬당 성공 시연 1,000개, 청크 길이 H=4, 11-D 전신 행동, AdamW 100k 스텝, cosine 감쇠, 배치 64. 청크의 처음 두 행동을 20 Hz로 실행 후 재계획. 실로봇: 과제당 200 시연, 4과제를 하나의 다중과제 정책으로 50k 스텝, 배치 64, 17-D 전신 행동(베이스 속도 vx, vy, ωz 포함). VLM 백본·쿼리·행동 헤드는 end-to-end로 학습된다. Qwen3-VL의 모델 크기, 전체 파라미터 수, 학습 하드웨어는 논문에 명시되지 않았다.

| MobileWAM | 46.0 | 46.0 | 63.7 | 64.7 | 99.3 | 91.0 | 100.0 | 73.0 |

## 8. 어블레이션과 분석 (Table III, SetTable)

| 변형 | Avg SR | ΔSR |
|---|---|---|
| Direct VLM Conditioning | 58.4 | −29.9 |
| Shared Query | 74.7 | −13.6 |
| w/o Joint Attention | 70.3 | −18.0 |
| w/o Corresponding Query Access | 66.3 | −22.0 |
| 뱅크당 쿼리 4개 | 74.6 | −13.7 |
| 뱅크당 쿼리 16개 | 82.5 | −5.8 |
| **MoPA (뱅크당 8개)** | **88.3** | – |

학습형 쿼리 집계(58.4→74.7)와 서브시스템 분리(74.7→88.3)가 모두 기여하고, 쿼리 상태를 행동과 함께 갱신하지 않거나(70.3) 각 행동 스트림이 두 뱅크를 모두 읽게 하면(66.3) 크게 떨어진다. 쿼리 수는 8개가 최적이며 16개로 늘리면 오히려 하락한다. 코사인 유사도 히트맵과 t-SNE는 두 쿼리 유형이 대체로 분리된 표현을 가진다는 정성적 근거를 제시한다(Fig. 4의 주의 시각화에서 Mobile Query는 바닥·주변 구조, Manip Query는 목표 물체 주변 선반에 집중).

## 10. 강점

- "행동 헤드 분리"와 "지각 조건 분리"를 구분해 문제를 명확히 정의하고, 이를 검증하는 어블레이션(Shared Query vs. 분리 쿼리, 대응 쿼리 접근 제거)을 설계했다.
- ManiSkill-HAB 세 스위트 전부에서 깊이 입력 베이스라인까지 포함해 RGB만으로 최고 평균을 기록했다.
- 스위트당 3×100 에피소드로 평가하고 표준편차를 보고한다.
- 실로봇 4과제를 하나의 다중과제 정책으로 처리했다.

## 11. 한계

- Qwen3-VL 크기, 전체 파라미터 수, 학습 자원, 추론 지연 등 재현에 필요한 핵심 정보가 빠져 있다.
- 시뮬레이션은 스위트별로 별도 정책을 학습해, 단일 범용 정책과의 비교에는 주의가 필요하다.
- 실로봇 평가는 과제당 20회로 작고, 베이스라인 수치가 그림에만 있어 정량 비교가 제한된다.
- 전자레인지처럼 관절 물체 상호작용이 포함된 과제에서는 이득이 없었다(π0.5와 동률, 55%).
- LIBERO·SimplerEnv 등 트래커의 표준 벤치마크 결과는 없다.

## 12. VLA-Tracker 관점 평가

Qwen3-VL 백본과 쿼리 뱅크, MoT 행동 헤드를 end-to-end flow matching으로 학습한 자체 모바일 매니퓰레이션 VLA이므로 수록 대상이다. 트래커 표준 벤치마크는 없어서 ManiSkill-HAB 세 스위트를 각각 별도 블록(`maniskill_hab_settable/tidyhouse/preparegroceries`)으로, 실로봇 4과제를 `real_world` 블록으로 기록하고, 베이스라인·어블레이션은 분리했다. 모바일 매니퓰레이션에서 "서브시스템별 지각–행동 대응"을 명시적 설계 원칙으로 제시한 사례로, 전신 제어 VLA 계열(MobileWAM, AC-DiT, GeoHAT 등)과 비교할 때 유용한 기준점이다.
