# DSWAM: A Dual-System World Action Foundation Model for Fine-Grained Robot Manipulation

**arXiv**: [2607.04927](https://arxiv.org/abs/2607.04927) · **기관**: AIRC, Midea Group (+ Tongji University) · **공개일**: 2026-07-06

---

## 1. 한 줄 요약

DSWAM은 World Action Model(WAM) 실행기(System 1)를 기본 제어 경로로 유지하고, 분해가 유익할 때만 VLM 서브태스크 플래너(System 2)를 선택적으로 가동하는 듀얼 시스템 세계-행동 파운데이션 모델로, 동일 로봇·데이터·평가 기준으로 통제된 DeMaVLA 실세계 접기 벤치마크에서 SR 92.5%→96.3%, 완료 시간 2'18''→1'44''를 달성하고 RoboTwin 2.0에서 clean 92.38% / randomized 91.90%로 최고 평균 성능을 기록했다.

## 2. 문제 설정 및 동기

WAM은 비디오 기반 세계 모델링을 밀집 감독 신호로 사용해 접촉이 많은 조작(파지, 배치, 변형체 조작)에서 강력하지만, 두 가지 공백이 있다. (1) VLM 기반 VLA가 제공하는 언어 수준의 계획 인터페이스가 없어, 거친(coarse) 가정용 지시를 세분화된 실행 가능 서브태스크 시퀀스로 분해하지 못한다. (2) 기존 WAM-VLA 비교는 데이터 소스, 로봇 신체(embodiment), 태스크 프로토콜이 제각각이어서 성능 차이가 정책 설계에서 온 것인지 실험 설정에서 온 것인지 불분명하다. DSWAM은 의미적 태스크 조직과 물리적 실행을 분리(decouple)할 수 있다는 관찰에서 출발한다: WAM은 강한 실행 엔진으로 남고, 상위 모듈은 분해가 필요할 때만 개입하면 된다.

## 3. 핵심 기여

1. **듀얼 시스템 WAM 프레임워크**: System 1(WAM 실행기)이 기본 제어 경로이고, System 2(비전-언어 서브태스크 플래너)는 분해가 유익한 경우에만 선택적으로 활성화 — 원자적(atomic) 지시에는 계획을 강제하지 않는다.
2. **통제된 WAM-VLA 실세계 비교**: DeMaVLA와 동일한 로봇 플랫폼, 사전학습 데이터, 사후학습 데이터, 태스크 프로토콜, 성공 기준 하에서 접기 벤치마크를 수행(System 2 비활성) — 정책 실행 능력 자체를 공정하게 비교.
3. **강력한 실증 결과**: 실세계 접기 SR 92.5%→96.3%, 완료 시간 2'18''→1'44''; RoboTwin 2.0 clean 92.38% / randomized 91.90%; 서브태스크 감독으로 정렬(sorting) 태스크 SR 75.7%→100%, 롤아웃당 실수 3.53→0.65.

## 4. 방법론

- **System 1 (WAM 실행기)**: 사전학습 비디오 모델(Wan2.2-TI2V-5B)과 액션 익스퍼트로 구성. 현재 멀티뷰 RGB(3뷰), 언어 조건, 고유수용성 상태를 잠재 세계 특징 z_t로 인코딩하고 액션 청크 A_t = [a_t, ..., a_{t+H-1}]를 예측. 학습은 공유 flow-matching 형식(y_τ = (1−τ)y + τε, 속도장 ε−y 예측)으로 액션 손실 L_act와 비디오 co-training 손실 L_vid를 결합(L = L_act + λ_vid·L_vid). 액션 토큰이 미래 시각 토큰을 특권 정보로 사용하지 못하게 차단하여 추론 시 설정과 정렬. **추론 시에는 미래 프레임을 샘플링·디노이징·디코딩하지 않고** 단일 순전파로 액션 청크를 직접 예측(Fast-WAM 계열의 효율적 WAM 방향).
- **System 2 (선택적 플래너)**: Rynnbrain4B-스타일 VLM. 전역 태스크 프롬프트 p와 1Hz로 샘플링된 최근 T=5 프레임의 시각 이력에서 다음 서브태스크 s_t = P_φ(X_t, p)를 예측. **전환 인지(transition-aware) 감독**: 서브태스크 내부 윈도우는 현재 라벨 s_k, 비종결 서브태스크의 마지막 윈도우는 다음 라벨 s_{k+1}, 종결 서브태스크의 마지막 윈도우는 'done' — 경계 근처에서 다음 지시를 발화하도록 학습. 배포 시 2초마다 5프레임 배치를 플래너에 전송해 서브태스크를 갱신.
- **배포 최적화**: 추론 시 RTC(real-time chunking) + 비동기 실행으로 정책 질의가 로봇 제어를 차단하지 않도록 분리(학습 시 액션 조건화나 suffix-only 손실은 사용하지 않는 배포 전용 메커니즘). TensorRT는 단일 그래프 대신 **2개 엔진**으로 분할: 시각-컨텍스트 엔진(레이어별 캐시 구축)과 액션-디노이징 엔진(캐시된 시각 상태를 소비해 디노이징 1스텝 갱신).

## 5. 실험 설정

- **RoboTwin 2.0**: 50개 양팔 조작 태스크, clean(고정 초기 배치)과 randomized(객체 자세·장면 무작위화) 설정, 태스크별 및 평균 SR 보고. 베이스라인: π0, π0.5, DeMaVLA, Fast-WAM, Motus.
- **매칭 실세계 접기 벤치마크**: DeMaVLA 프로토콜 준수. ALOHA-스타일 듀얼암, 셔츠/스커트/바지/수건 4개 변형체 태스크, 카테고리당 2개 의류 인스턴스(easy + hard; hard는 미수집 또는 노후 의류) × 10회 = 20회. 바구니에서 꺼내 테이블에 펼치고 접는 전체 절차. **System 2는 가동하지 않음**(WAM-only 모드). 실패 시행은 타임아웃 시간으로 계산.
- **System 2 정렬 연구**: "Sort objects on the table"이라는 거친 지시를 2개 서브태스크(장난감 자동차→상자, 빵→접시)로 분해한 감독과 원시 지시 감독을 비교.
- **효율성**: RTX 5090, CUDA 12.9, TensorRT 10.16.1에서 배치 1 warmed end-to-end 정책 지연 측정, 6개 시드에서 PyTorch 참조와의 액션 일치도 측정.

## 6. 주요 결과

- **RoboTwin 2.0 (Table 1)**: DSWAM 평균 clean 92.38% / randomized 91.90% — 양쪽 모두 최고. DeMaVLA(최강 VLA 베이스라인) 대비 +3.96%/+5.12%, π0.5 대비 +9.64%/+15.14%, Fast-WAM 대비 +0.50%/+0.12%.
- **실세계 접기 (Table 2)**: 평균 SR 96.3%, 완료 시간 1'44'' — DeMaVLA 대비 SR +3.8%p, 시간 −34초; π0 대비 SR +20.0%p, 시간 −42초. 바지에서 가장 큰 개선(75.0%→90.0%, 3'01''→2'19''), 스커트/수건은 100% 유지하며 롤아웃 대폭 단축, 셔츠는 95.0% 동률에 약간 더 빠름.
- **System 2 연구 (Table 3)**: 원시 지시 학습은 평균 SR 75.7% / 롤아웃당 실수 3.53, 서브태스크 감독은 SR 100% / 실수 0.65(18k 스텝에서 0.30)로 실행 안정성 대폭 개선.
- **효율성 (Table 4, 5)**: BF16 TensorRT로 198.2ms→73.8ms(2.69× 속도 향상), 최대 상대 오차 0.0106, 코사인 유사도 0.99977. 비동기 TensorRT+RTC는 easy 인스턴스에서 바지 SR 70%→100%, 셔츠 성공 시간 1'47''→1'28''.

## 7. Ablation 분석

- **서브태스크 감독의 효과 (Table 3)**: 동일 실행기에서 학습 스텝(6k/18k)을 통제한 채 지시 형식만 바꾼 비교 — 원시 지시는 18k 스텝에서도 80.0% SR / 실수 3.30에 머무르는 반면, 서브태스크 지시는 6k 스텝만으로 100% SR을 달성. 명시적 서브태스크 컨텍스트가 오류 누적을 줄임을 시사.
- **배포 메커니즘 분리 (Table 5)**: 동기식 TensorRT vs 비동기 TensorRT+RTC를 easy 의류 인스턴스에서만 별도 평가 — 바지 SR 70%→100%로, 정책을 바꾸지 않고 추론-제어 분리만으로 실행 안정성이 개선됨을 입증. 접기처럼 연속 양팔 조작과 접촉 기반 미세 조정이 필요한 태스크에서 빈번한 액션 갱신이 중요.
- 다만 λ_vid(비디오 co-training 가중치)나 video co-training 자체의 유무에 대한 직접 ablation은 보고되지 않았다.

## 8. 이전 연구와의 비교

DreamZero(비디오 확산 백본으로 미래 비디오+액션 공동 예측), Cosmos Policy(비디오 파운데이션 모델 파인튜닝), Motus(이해·비디오 생성·액션 통합), LingBot-VA(인과적 비디오-액션 모델링) 등 기존 WAM은 주로 실행 정책으로 설계되어 언어 수준 태스크 조직이 미비했다. GigaWorld-Policy와 Fast-WAM은 세계 모델링의 이득이 학습 시 감독에서 오며 테스트 시 미래 상상이 불필요할 수 있음을 보였고, DSWAM은 이 노선을 따라 추론 시 미래 비디오 생성을 제거했다. 차별점은 (1) 선택적 System 2 플래너로 분해 능력을 추가하되 원자적 지시에는 강제하지 않는 설계, (2) DeMaVLA와 완전히 매칭된 조건의 실세계 WAM-VLA 비교라는 방법론적 기여다. RoboTwin 2.0에서 Fast-WAM(91.88/91.78) 대비 소폭이지만 일관된 우위를 보였다.

## 9. 강점

- **통제된 비교 설계**: 로봇 플랫폼, 사전/사후학습 데이터, 태스크 정의, 성공 기준을 모두 DeMaVLA와 매칭하고 System 2까지 끈 상태로 비교 — WAM 실행이 VLA를 능가한다는 주장에 대해 드물게 깨끗한 실세계 증거.
- **선택성(optionality)의 설계 철학**: 계획을 항상 강제하는 기존 계층형 시스템과 달리, 분해가 유익할 때만 System 2를 가동 — 원자적 태스크에서 불필요한 지연과 오류 전파를 회피.
- **배포 엔지니어링의 완성도**: 2-엔진 TensorRT 분할(공개 서빙 인터페이스 보존), RTC, 비동기 실행의 조합을 정량 프로파일링(2.69× 속도, 코사인 유사도 0.99977)과 실로봇 롤아웃 개선으로 모두 검증.
- 5,000시간 이상의 실세계 듀얼암 휴머노이드 데이터 기반의 확장 가능한 사전학습.

## 10. 약점 및 한계

- **video co-training의 직접 ablation 부재**: L_vid 유무나 λ_vid 민감도를 보고하지 않아, 성능 이득이 세계 모델링 감독에서 오는지 백본/데이터 규모에서 오는지 분리가 어렵다.
- **System 2 평가의 협소함**: 정렬 태스크 1개(서브태스크 2개)에서만 검증 — 긴 다단계 가정용 태스크에서 플래너의 일반화나 오류 복구는 미검증. 플래너 활성화 여부를 누가/어떻게 결정하는지(자동 판단 기준)도 명시되지 않았다.
- **접기 벤치마크의 규모**: 카테고리당 20회 시행(총 80회)으로 3.8%p 차이의 통계적 유의성은 논하기 어렵다.
- 코드 미공개(프로젝트 페이지만 존재), 액션 익스퍼트 파라미터 수·학습 스케줄 등 세부 사항 일부 미보고. System 2는 1 FPS 고정 샘플링으로 학습되었는데 실로봇의 가변 주파수 입력에 대한 강건성은 정성적 관찰에 그친다.

## 11. 향후 연구 방향

플래너 활성화의 자동 판단(언제 분해가 유익한지 학습으로 결정), 더 긴 다단계 가정용 태스크에서의 System 2 검증, video co-training 기여의 정량적 분리, System 1-System 2 간 피드백(실행 실패 시 재계획) 루프 추가가 자연스러운 다음 단계다. 또한 매칭 비교 방법론을 접기 외 태스크군과 다른 embodiment로 확장하면 WAM-vs-VLA 논쟁에 더 일반적인 답을 줄 수 있다.

## 12. 세미나 토론 질문

1. 추론 시 미래 비디오 생성을 제거해도 성능이 유지된다면, video co-training이 주는 이득의 본질은 무엇인가 — 표현 학습 정규화인가, 물리 역학의 암묵적 인코딩인가? L_vid를 끈 ablation이 없다는 점에서 이 주장을 어떻게 검증할 수 있는가?
2. System 2를 "선택적"으로 두는 설계에서, 어떤 지시가 분해를 필요로 하는지의 판단은 현재 사람의 몫이다. 이 게이팅을 학습 기반으로 만들면 어떤 실패 모드가 생길까?
3. 매칭 접기 벤치마크에서 DSWAM(96.3%)과 DeMaVLA(92.5%)의 차이는 정책 형식(WAM vs VLA)에서 오는가, 백본(Wan2.2 video model vs VLM)의 사전학습 데이터 특성에서 오는가?
4. 비동기 TensorRT+RTC가 바지 SR을 70%→100%로 끌어올린 것은 "배포 최적화가 곧 성능"임을 시사한다. 정책 비교 벤치마크에서 추론 지연을 통제 변수로 표준화해야 하는가?
