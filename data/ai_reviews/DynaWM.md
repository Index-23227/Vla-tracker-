# DynaWM: A Base-VLA-Guided World Foundation Model for Moving-Object Manipulation

**arXiv**: [2607.02604](https://arxiv.org/abs/2607.02604) · **기관**: Tsinghua University (THUAI) · **공개일**: 2026-07-01

---

## 1. 한 줄 요약

DynaWM은 동결(frozen)된 임의의 base VLA가 출력하는 액션 청크를 Mamba-3 인코더로, 최근 5프레임×3뷰 관측 이력을 V-JEPA 2.1로 인코딩하여 flow-matching DiT가 움직이는 물체를 요격(interception)하는 새 액션 청크를 노이즈로부터 재생성(regeneration)하는 base-VLA-유도 세계 파운데이션 모델로, 자체 구축한 DynaGrasp-32 벤치마크에서 SmolVLA/X-VLA/π0/π0.5의 fine-tuned·coarse-tuned 8개 조합 전부의 평균 성공률을 개선했다(fine-tuned +1.88~+45.31%p, coarse-tuned +26.13~+44.06%p).

## 2. 문제 설정 및 동기

대부분의 VLA는 정지된 물체 또는 로봇 팔 자신의 접촉으로만 움직이는 물체를 다룬다. 독립적으로 움직이는 표적의 요격은 관측→액션 생성→실행 사이의 지연 동안 표적이 이미 이동해 있으므로, 현재 관측 위치만 겨냥하면 반응적 추적(reactive tracking)에 그친다. 기존 해법(월드 모델을 각 VLA에 직접 통합, AHEAD처럼 특정 모델의 표현 공간에서 미래 토큰 예측)은 모델 고유의 시각 토큰·액션 디코더·학습에 종속된다. DynaWM의 핵심 관찰은, VLA들의 내부 토큰 공간은 제각각이어도 출력 액션 궤적은 물리적 의미(조작 대상, 접근 방향, 파지 단계)를 공유하므로, 액션 청크 자체를 조건 신호로 쓰면 이종 base VLA에 공통 적용 가능한 하나의 세계 파운데이션 모델을 만들 수 있다는 것이다. 누락된 신호는 "장면이 어떻게 변하는가"이며, 이는 멀티뷰 관측 이력으로 보충한다.

## 3. 핵심 기여

1. **Base-VLA-유도 세계 파운데이션 모델**: 동결된 base VLA의 언어/시각 토큰, 은닉 상태, 그래디언트에 접근하지 않고 방출된 액션 청크만을 조건으로 사용 — base VLA 아키텍처를 수정하지 않고 다양한 fine-tuned/coarse-tuned 체크포인트에 적응.
2. **액션 재생성 모듈**: Mamba-3 액션 인코더 + V-JEPA 2.1 비전 인코더 + 고유수용성 상태 인코더 + flow-matching DiT — 세 조건이 공동으로 DiT를 조건화하여 움직임 인지(motion-aware) 실행 궤적을 재생성.
3. **DynaGrasp-32 벤치마크 + DynaGrasp-1600 데이터셋**: 6개 진단 태스크군(기본 요격, 외형/기하 전이, 충돌 경로 변화, 시각 변화, 다중 물체 순서화, 속도 변화), 32개 시나리오, 1,600개 시연 궤적, 약 1.53M 이미지 — 4개 base VLA × 2개 체크포인트 유형 = 8개 조합 전부에서 1.88~45.31%p의 일관된 개선.

## 4. 방법론

- **문제 정식화**: base VLA π_b가 현재 관측 o_t, 지시 ℓ_t, 상태 s_t로부터 base 액션 청크 A^b_t ∈ R^{H×D_a} (H=10, D_a=7)을 예측. DynaWM g_θ는 Â_t = g_θ(A^b_t, V_t, s_t)를 산출하며, V_t는 t에서 끝나는 짧은 멀티뷰 비디오. base VLA 체크포인트는 고정되어 DynaWM 학습 중 갱신되지 않는다.
- **Mamba-3 액션 인코더**: 차원별 정규화된 액션 청크를 궤적 순서로 처리, 128차원 Mamba 상태를 거쳐 256차원 액션 조건 표현 z_a를 생성(마지막 유효 스텝의 표현이 선행 제어 시퀀스를 요약). 인접 액션이 제어 연속성으로 결합되어 있어 상태공간 모델의 순환 스캔이 적합하다는 논거.
- **V-JEPA 2.1 시각 인코더**: 뷰별(K=3) 최근 L=5 프레임 클립을 공유 V-JEPA 2.1 ViT-L(300M)로 밀집 시공간 토큰 Z_v로 인코딩. **미래 이미지나 잠재 상태 롤아웃 없음** — 프레임 간 변위가 방향·상대속도·반동·가속 증거를 제공. V-JEPA 인코더는 DynaWM의 학습 가능한 부분(동결은 base VLA만).
- **Flow-matching DiT 생성기**: 8개 트랜스포머 블록, 512차원 은닉, 8 어텐션 헤드. 전역 조건 c_0 = [z_a; z_s]는 AdaLN으로 주입, 시각 모션 토큰 Z_v는 풀링 없이 크로스어텐션으로 주입. 선형 확률 경로 x_τ = τx_1 + (1−τ)x_0 (x_1 = 시연 청크, x_0 = 가우시안 노이즈)에서 속도장 v_θ를 MSE로 학습. 추론 시 N(0,I)에서 샘플링 후 Euler 10스텝 적분.
- **"재생성" 설계**: base 액션 청크는 조건일 뿐 초기 샘플이 아니며, 출력이 A^b_t + ΔA 형태로 제약되지 않음 — 노이즈에서 시작하면 반응적 base 청크가 낡은 표적 위치를 가리킬 때 더 큰 교정이 가능(잔차/청크 초기화 flow는 국소 수리로 편향될 위험).
- **학습 파이프라인**: 각 base VLA를 시연 데이터에 한 번 실행해 base 액션 청크를 캐싱 → 캐시된 청크 + 멀티뷰 이력 + 상태 + 시연 청크로 학습(학습 그래프에 base VLA 없음). 아키텍처·최적화 레시피는 4개 base VLA에 공통, 가중치는 base VLA별 분리.

## 5. 실험 설정

- **DynaGrasp-32**: Isaac Sim, Franka Panda, 256×256 RGB 3대, 9D 상태, 7D 액션, 30Hz. 6개 태스크군: Base(2, 직교 이동 방향 기본 요격 — 공을 0.20m 이상 들어올리기), Objects(6, 색/모양/크기/방향 전이), Obstacle(6, 충돌면과 반동), Environment(6, 조명/바닥/방해물), Amount(6, 다중 물체·용기 바인딩 순서화 — 전부 올바르게 배치해야 성공), Speed(6, 에피소드별 속도 변화). 나머지 태스크는 대체로 언어로 지정된 바구니에 움직이는 물체를 배치.
- **DynaGrasp-1600**: 태스크당 50개 인간 원격조작 시연, 총 1,600 궤적, ~510K 스텝, 1.53M 이미지.
- **평가**: SmolVLA, X-VLA, π0, π0.5를 fine-tuned(SmolVLA/X-VLA 4-5 에폭, π0/π0.5 2-3 에폭)과 coarse-tuned(~0.5 에폭) 체크포인트로 준비. 모델-태스크 구성마다 closed-loop 50 에피소드(32태스크 매크로 평균 = 1,600 에피소드 풀링 성공률). 증강/비증강 평가는 동일한 동결 체크포인트 사용. NVIDIA RTX PRO 6000(96GB)에서 실험.

## 8. 이전 연구와의 비교

DynamicVLA·PUMA는 동적 장면용 인지-제어 공동 학습, ST-VLA·LaMP·OFlow는 4D/장면 흐름 모션 사전, F2F-AP는 비동기 정책 지연 보상용 미래 관측 예측을 쓰지만 모두 전용 동적 정책을 학습하거나 특정 정책의 특징 공간 내부에서 동작한다. 가장 가까운 AHEAD는 동결 OpenVLA를 감싸지만 그 모델 고유의 표현 공간에서 미래 토큰을 예측한다. Cosmos/Cosmos 3 계열 세계 파운데이션 모델과 달리 DynaWM은 비디오 생성이 아닌 액션 재생성이 출력이며, 미래 프레임 롤아웃 자체를 하지 않는다. Streaming Flow Policy·Real-Time Chunking·FASTER 등 청크 갱신 계열과도 구분: DynaWM은 언제 재생성할지가 아니라 무엇으로 조건화할지를 다룬다. 차별점은 정책 내부 표현에 접근하지 않는 base-action-conditioned 생성이 구조가 다른 여러 동결 base VLA에 하나의 아키텍처·레시피로 적용된다는 점이다. 벤치마크 측면에서는 DGBench·DOMINO 등 동적 조작 벤치마크가 있으나, 이종 base-VLA 체크포인트 간 동일 closed-loop 비교를 지원하는 진단 스위트로 DynaGrasp-32를 위치시킨다.

## 9. 강점

- **모델 불가지론적 인터페이스**: 액션 청크라는 물리적으로 공유된 출력만 조건으로 사용 — 토큰 공간·디코더·차원이 다른 4개 VLA(autoregressive~flow 계열 혼재)에 동일 아키텍처로 적용되고 8/8 조합에서 개선.
- **깨끗한 통제**: 증강/비증강 평가가 동일한 동결 체크포인트를 사용하므로 개선을 base-VLA 재학습으로 귀속시킬 수 없음. 학습 그래프에 base VLA가 없어 캐싱 후 학습이 저렴.
- **설계 선택의 실증적 뒷받침**: "재생성 vs 잔차/초기화"(29.00% 붕괴), "인코딩된 조건 vs 직접 시작", V-JEPA 규모 효과(80M→300M) 등 핵심 설계마다 진단 실험이 붙어 있음.
- **재현 가능한 벤치마크 기여**: 하나의 동적 난이도 요인만 변화시키는 6개 태스크군 설계, 태스크당 50 에피소드의 closed-loop 평가 프로토콜.

## 10. 약점 및 한계

- **시뮬레이션 한정**: 모든 결과가 Isaac Sim(Franka Panda) 내이며 실로봇 검증이 없다. 저자들도 DynaGrasp-32를 "후속 하드웨어 검증을 위한 통제된 기반"으로 위치시킨다. 실세계의 지각 노이즈·지연 하에서 5프레임 이력 기반 모션 추정이 유지될지 미검증.
- **강한 base VLA에서의 퇴보**: fine-tuned π0는 14개 태스크에서 퇴보(Up/Tie/Down 14/4/14, 순이득 +1.88에 불과)하며, 특히 Amount에서 국소 모션 교정이 유효한 물체 순서·언어 바인딩을 교란 — 언제 재생성을 신뢰할지의 게이팅 메커니즘이 없다.
- **base VLA별 가중치 분리**: "파운데이션 모델"을 표방하지만 실제로는 base VLA마다 별도 DynaWM 가중치를 학습 — 단일 가중치로 미지의 base VLA에 zero-shot 적응하는지는 미검증.
- **추론 지연 미보고**: base VLA 추론 + DynaWM(Euler 10스텝) 직렬 파이프라인의 실시간성(30Hz 환경 대비)이 정량 보고되지 않았다. 동적 조작에서 지연은 핵심 변수인데 아이러니하게도 분석이 없다.
- 코드/데이터셋 공개 여부가 논문에 명시되지 않았고, LIBERO 등 표준 정적 벤치마크와의 접점이 없어 기존 리더보드와의 직접 비교 불가.

## 11. 향후 연구 방향

(1) 실로봇에서의 하드웨어 검증과 지연 분석, (2) base VLA별 분리 가중치를 넘어 다중 base VLA에 공유되는 단일 가중치 또는 zero-shot 적응, (3) 강한 base VLA에서의 퇴보를 막는 재생성 신뢰도 게이팅(base 청크를 그대로 실행할지 재생성할지의 선택 학습), (4) Amount류 순서화 실패를 다루기 위한 언어 바인딩 조건의 통합, (5) Mamba-3 외 대안적 시계열 인코더 비교(저자들이 명시적으로 열어둔 방향)가 자연스러운 다음 단계다.

## 12. 세미나 토론 질문

1. base 액션 청크가 언어·시각 토큰 없이도 "무엇을 조작할지"를 충분히 전달한다는 주장(Table 5a)은 단일 태스크-단일 지시 설정의 산물일 수 있다. 하나의 장면에 여러 유효 목표가 있고 지시로만 구별되는 경우(Amount류), 액션 조건만으로 의미적 모호성을 해소할 수 있는가?
2. 노이즈에서의 재생성이 base-청크 초기화보다 훨씬 낫다는 결과(74.44% vs 29.00%)는 flow 초기화 분포와 학습 분포의 불일치 때문일 수도 있다. base 청크 초기화 방식을 그에 맞게 학습시켰다면(예: 브리지형 flow) 결론이 뒤집힐 가능성은?
3. fine-tuned π0에서 14개 태스크 퇴보는 "능력 보상" 프레임의 한계를 드러낸다. base VLA가 이미 옳을 때 DynaWM이 개입을 자제하게 만들려면 어떤 신호(예: base 청크와 재생성 청크의 괴리, 시각 모션 크기)를 게이트로 쓸 수 있는가?
4. DynaWM은 미래 프레임을 생성하지 않으면서 "world foundation model"을 표방한다. V-JEPA류 표현 예측 기반 모듈을 세계 모델로 부르는 것이 Cosmos류 생성적 세계 모델과 같은 범주로 묶일 만큼 개념적으로 정당한가?
5. 30Hz 환경에서 base VLA + Euler 10스텝 DiT의 직렬 추론이 실시간으로 가능한가? 만약 지연이 크다면, 이 지연 자체가 요격해야 할 δ_t를 키우는 자기 참조적 문제가 되지 않는가?
