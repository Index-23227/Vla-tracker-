# AdaDE — Dense to MoE Adaptation for Compact Vision Language Action Policies

- arXiv: 2609.16503 (PDF 스탬프 v2, 2026-09-18; v1 날짜는 논문에 명시되지 않음)
- 소속: Shanghai Jiao Tong University, Tianji KernalMind Co., Ltd., Alibaba Group
- 학회: Not stated in the paper / 코드 공개: Not stated in the paper

## 1. 한 줄 요약

AdaDE는 π0.5의 LLM 측 FFN(언어 모델 + action expert)을 기능 보존형 MoE로 재구성(Dense2MoE)한 뒤, 파인튜닝 중 라우터 통계로 전문가를 점진적으로 비활성화해 **LLM 파라미터의 약 40%를 제거하고도** LIBERO 3-suite 평균 95.7%, RoboTwin2.0 50과제 평균 42.0%(dense 46.7%)를 유지하는 압축 방법이다.

## 2. 문제 설정

VLA 파라미터의 상당 부분이 언어 백본에 몰려 있어 자원 제약 로봇 배포가 어렵다. 저자들의 예비 실험에서 ViT와 행동 생성 모듈은 압축에 민감한 반면 LLM 백본은 중복이 크다. 기존 dense 구조적 가지치기는 사전학습 함수를 바꿔 별도의 복구 튜닝이 필요하고, dense VLA는 MoE식 조건부 계산(전문가 스킵·비활성화)을 활용할 수 없다.

## 3. 핵심 아이디어

(1) dense FFN을 중간 채널 방향으로 연속 슬라이스해 전문가로 나누고 라우터를 0으로 초기화하면 초기 MoE 출력이 dense 출력과 정확히 같다(복구 단계 불필요). (2) 고정 희소도 대신, 층마다 EMA로 평활한 라우터 사용률을 기준으로 약한 전문가를 점진적으로 끄는 적응형 비활성화를 파인튜닝과 동시에 수행한다.

## 4. 아키텍처

기반: π0.5(PaliGemma Gemma-2B + Gemma-300M action expert + SigLIP). 총 63개 FFN 모듈을 모듈당 10개 전문가로 변환하고, 그중 36개 LLM/action-expert 모듈에 동적 비활성화를 적용한다. 출력은 활성 전문가에 대해 마스킹 후 재정규화한 라우터 확률에 N_r을 곱한 soft 가중합으로, 일반적인 token-level top-k 디스패치 MoE가 아니라 압축용 폭-분할·마스크 기반 MoE다. 학습 후 비활성 전문가 슬라이스는 체크포인트에서 물리적으로 제거된다. 파라미터: dense 3.618B → 40% 설정 2.841B, 50% 설정 2.619B(ViT 0.268B·Flow 1.307B 불변).

## 5. 학습과 추론

손실 = 원래 과제 손실 + λ·L_aux(각 층 최소 평균 라우터 확률이 τ_aux 아래로 떨어지면 벌점; 균등 부하가 아니라 조기 붕괴만 막음). 3단계: warmup(1,000 스텝, 모든 전문가 활성, Wanda 기준 상위 25% 전문가 보호 지정) → 동적 비활성화(100 스텝마다 EMA 점수 τ_deact=0.08 미만 후보 제거, 층당 최소 5/10 활성, 재활성화 없음) → 15,000 스텝에서 마스크 고정. 총 40,000 스텝, AdamW, 최대 LR 5e-5. 추론 시 남은 전문가만 포함된 compact 체크포인트를 사용한다.

LIBERO-Long은 보고되지 않았다(초록의 "LIBERO 평균 95.7%"는 3 suite 기준). RoboTwin2.0 50개 DemoClean 과제 평균: Base 46.68, 0% 46.44, 40% 42.00, 50% 38.06 (TFLOPs 4.38 → 3.18 → 2.90). 실로봇 7과제(Table VI): π0.5 평균 63.2% vs AdaDE(40%) 61.4%, 피크 메모리 9.16 → 7.48 GB.

OpenVLA LIBERO-Spatial: 원본 84.7(7.5B). LLM-Pruner 23.4 → SFT 후 84.0(6.2B), FLAP 0.2 → SFT 후 82.6(6.3B), 8bit 84.6, 4bit 81.0, magnitude 83.4, Wanda 84.0. AdaDE 20% 84.3(6.2B), 30% 82.0(5.6B)로 별도 복구 SFT 없이 비슷한 수준. π0.5 피크 VRAM(B=1)은 7.12 → 5.69(40%) / 5.25 GB(50%).

## 8. 어블레이션 (Table III, LIBERO-Spatial, 30k 스텝, 50% 제거)

Base 98.6 / 고정 스케줄 제거 88.0 / Wanda 보호 없음 90.0 / AdaDE 95.0 / 갱신 간격 50 스텝 68.0 / 500 스텝 93.0. 너무 잦은 마스크 갱신이 크게 불안정하다는 점이 눈에 띈다. Figure 3(b)는 action 쪽 모듈이 언어 쪽보다 비활성화에 훨씬 민감함을 보인다(수치는 그림으로만 제시).

## 9. 분석

층·모듈마다 압축 허용도가 다르며, 같은 총 제거율에서도 언어/행동 모듈 간 배분에 따라 성능이 달라진다. 40→50%로 갈 때 성능 저하가 급격하지 않고 점진적이어서 "임계점"보다는 "운용 범위"에 가깝다고 저자들은 해석한다.

## 10. 강점

- 초기화 시 정확히 기능 보존되는 변환이라 복구 단계 없이 압축으로 진입할 수 있다(부록에 등가성 증명).
- RoboTwin2.0 50과제 전체 결과와 실로봇 7과제를 모두 공개해 선택 편향을 줄였다.
- 가지치기·양자화 등 다양한 압축 기준선과 VRAM까지 비교했다.

## 11. 한계

- 저자 스스로 밝히듯 **지연 시간은 오히려 증가**(dense 212 ms vs 50% AdaDE 236 ms, B=1): 라우팅·소형 GEMM 오버헤드 때문. 메모리/파라미터 절감이 주 효과다.
- LIBERO-Long이 빠져 있어 표준 4-suite 평균과 비교할 수 없다.
- RoboTwin은 clean 단일 설정만 보고(표준 Easy/Hard 쌍 아님), 40% 설정에서 4.7pt 하락은 작지 않다.
- 실로봇 과제별 시행 횟수, 로봇 플랫폼이 명시되지 않았다.
- 스케줄 하이퍼파라미터(warmup, ΔT) 민감도가 크다.

## 12. VLA-Tracker 관점 평가

압축 방법이지만 π0.5(및 OpenVLA)를 실제로 파인튜닝하면서 가중치와 라우터를 학습해 자체 compact 정책을 만들므로 수록 대상이다(학습 없는 추론 가속/양자화와 구별됨). LIBERO는 Long이 없어 순위용 `libero` 블록 대신 `libero_3suite` 별도 블록에, RoboTwin2.0은 clean 단일 설정이라 `robotwin_v2_50task_clean` 별도 블록에 기록했다. "파라미터 40% 감소 대비 성능 유지" 축의 참고점으로 유용하지만, 속도 향상은 아직 없다는 점을 함께 봐야 한다.
